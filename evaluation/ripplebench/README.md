# RippleBench — 健康事件涟漪守护智能体量化评测基准

> "测试通过"证明系统能跑，"评测分数"证明系统做得好。RippleBench 用 60 个标准化临床病例，
> 把作品的核心能力变成可复现、可对照、可被评委质疑的硬数字。

## 一、为什么需要它

医疗AI评委必问三件事：**你的分诊准不准？你怎么证明推演没有漏？护栏会不会既漏报又误报？**
此前项目只有功能性端到端测试（19步旅程全部通过），能证明"管道通"，不能证明"质量高"。
RippleBench 补上这一层：**预注册达标线 → 标准病例集 → 自动跑分 → 报告留档**。

## 二、评测集构成（60例）

| 子集 | 数量 | 测什么 | 核心指标 |
|---|---|---|---|
| T 分诊路由 | 20 | 症状自然语言→科室+紧急度+降级标记三元组 | top-1准确率（达标线≥90%） |
| R 涟漪推演 | 20 | 五维图谱知识命中+RII强度指数+时间学类型覆盖 | 用例通过率（达标线≥90%）、RII有效率（100%） |
| G 反事实护栏 | 20 | 危险场景必须FLAGGED（灵敏度100%）；良性场景不得误锁（特异度100%） | 灵敏度/特异度 |

病例设计覆盖：急症红色指征（胸痛/卒中/哮喘持续状态）、优先级覆盖（代谢症状+胸闷→心内优先）、
真实降级（非特异症状诚实降级人工分诊）、单病/多病共存/药物主导/药物联用/知识库未覆盖疾病（优雅空态）。

## 三、方法论要点（评委可质疑点的预设回答）

1. **金标准从哪来？** 分诊金标准按临床分诊常规人工制定（20例含专家共识级别的急症指征）；
   涟漪金标准依据作品内置循证知识库（13药物冲突/12并发症信号/9复查窗/11时间学规则）反向构造——
   测的是"知识库→图谱→RII→护栏"全链路的工程正确性，而非知识库医学内容的完备性（后者由指南对齐的Timing Card背书）。
2. **防挑数字。** 达标线在 `run_eval.py` 的 `THRESHOLDS` 中预注册，报告同时给出实测值与达标线。
3. **评测驱动改进闭环。** v1首轮评测暴露2处真实缺陷（见下），修复后v2复测——这是"工程质量"的最硬证据。
4. **可复现。** 一条命令重跑：`py -3 evaluation/ripplebench/run_eval.py`，报告写入 `reports/`。

## 四、版本改进记录

- **v1（2026-09-15 凌晨首轮）**：T20例中暴露2处规则缺口——
  (1) 卒中/意识类红色指征（意识不清/言语不清/偏瘫/面瘫）未覆盖，落入降级兜底（**安全缺口**：急症被当普通病）；
  (2) 哮喘+呼吸困难被心血管规则优先误路由至心内科（**急症误分流**）。
  G20例：10危险场景全部正确FLAGGED，10良性场景0误锁（护栏质量一次达标）。
- **v2（2026-09-15 修复后）**：ai-service规则引擎新增**优先级0层**（神经急症红色指征→急诊分流；
  哮喘持续状态→呼吸急症），`medical-triage` Skill危险词表同步补齐卒中三联征。
  报告见 `reports/ripplebench_report.md`。

## 五、运行

```bash
# 前置：docker compose -f deploy/docker-compose.yml up -d（全栈healthy）
py -3 evaluation/ripplebench/run_eval.py            # 默认网关 http://localhost:18080
py -3 evaluation/ripplebench/run_eval.py --base-url http://localhost:18080
```

退出码 0=全部达标；1=存在未达标项（可直接接入CI）。

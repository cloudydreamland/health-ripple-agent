## 一、严格对照官方五维（100分）

### 创新性（30分）— 官方考察点：场景、技术方案及AI功能实现是否新颖独特，有突破

**本作品回答**：健康事件涟漪守护——事件触发的多维连锁影响推演（新诊断/新处方发生时，主动推演用药冲突/复查窗口/并发症信号/家属注意/触达时机），30+ 竞品交叉验证无一对标；RII 把"涟漪"从比喻升级为可计算模型（RII=100×S×U×A×e^(−0.22(r−1))，阈值推导写入代码注释、单调性单测约束、可复算）；反事实护栏+哈希链存证、五Agent MDT、72小时预报、守护价值账本。

**现场证据**：作品说明文档第十一章（竞品对比）；大屏 FIG.01-06；RippleIntensityModelTest。

**⚠️ 评委可能抨击 × 防御**：
- "主动提醒早就有" → 防御：提醒是"定时定性"，我们是"事件触发+定量推演+干预时机计算（Timing Card 循证）+责任证据固化"——比的是维度不同。
- "推演结果是编的吧" → 防御：每节点 S/U/A/衰减四项评分依据可展开、可复算，RII-SPEC 开放规范允许任何人复现。

### 技术实现（30分）— 官方考察点：技术方案运用是否合理，运行是否稳定高效，AI功能是否深入

**本作品回答**：13 个 Spring Boot 3 微服务 + 5 个 DuMate Skill（Agent Skills 开放标准）+ MCP Server + 事件驱动（RabbitMQ）；**分级 AI 策略**：ai-service 内置可插拔 Provider（Dify 工作流 / OpenAI 兼容 LLM / 规则引擎），生产环境配 LLM Key 即全 AI 推理，无 Key/断网自动降级规则引擎且输出如实标注 degraded 与 provider 来源——"AI 失败不中断流程、不假装没失败"；SHA-256 哈希链（并发安全有专项回归测试）、FHIR R4 Provenance 导出（NIST 官方 OID）。

**现场证据**：E2E 27/27；单测全绿；RippleBench v3（开发集60例+盲测集10例分离）；四轮评测修复 8 处真缺陷（含哈希链并发分叉）；`docker compose ps` 21+ 容器全 healthy。

**⚠️ 评委可能抨击 × 防御**：
- **"你们现场跑的是规则引擎，不是真 AI"（最锋利的一刀，必须有预案）** → 防御三段：①现场演示真连后端的完整链路（分诊/处方拦截/涟漪推演全部出结构化结果+证据链，无 degraded）；②架构上 LLM Provider 是配置项（application.yml 一行切换 Dify/OpenAI），演示环境受比赛算力与 Key 限制走规则引擎，这是**工程上的分级可用性设计而非能力上限**；③规则引擎本身不是 if-else 玩具：症状匹配带否定感知（"无胸痛"不作阳性证据）、急诊红色指征分级、分诊安全网覆写——有单测锁定行为。
- "评测是自己考自己" → 防御：开发集/盲测集分离（held-out），盲测首轮抓到 2 处真缺陷并修复，全过程可追溯（评测报告 v3.1 版本记录）。
- "Skill 连不上后端吧" → 防御：现场 DuMate 真连演示；技能按角色鉴权（分诊用患者令牌、处方用医生令牌），网关 JWT 校验，证据链落库。

### 实用价值（20分）— 官方考察点：能否切实解决行业问题，是否具备推广应用潜力

**本作品回答**：对准基层医疗五个有政策与监管文件背书的真痛点——

1. **处方审核是法定动作**：《医疗机构处方审核规范》（国卫办医发〔2018〕14号）明确"**所有处方均应当经审核通过后方可进入划价收费和调配环节**"，药师是第一责任人——本作品处方安全 Skill 就是把"逐单人工审"升级为"AI 前置拦截 + 药师/医生终审"，直接服务该规范的落地执行（来源：国家卫健委官网解读）。
2. **慢病随访是公卫硬指标**：《国家基本公共卫生服务规范（第三版）》要求高血压、2型糖尿病患者**每年至少 4 次面对面随访 + 1 次健康体检**，控制不满意需及时转诊——本作品随访 Skill 的"计划生成/用药提醒/随访问卷/异常主动回传医生"正是这条管理链条的自动化执行（来源：国家卫健委、中国疾控中心官网）。
3. 误分诊/急诊识别延误；4. 病历耗时/要素遗漏；5. 医疗 AI 黑盒不可审计。

商业模式：守护人年计费、合规存证按条计费、MDT 按例计费等八项（应用方案第十五章）。

**现场证据**：应用方案第三/十五章；演示八条指令逐条对应一个痛点。

**⚠️ 评委可能抨击 × 防御**：
- "基层医院凭什么信学生作品" → 防御：信创适配（Kingbase）+ 私有化部署 + 医生终审权设计（AI 只拦截不建议药、不开方）——卖点是"合规守护"不是"替代医生"。
- "数据从哪来" → 防御：内置知识库+指南 Timing Card 演示闭环；接 HIS/EMR 的集成路径在应用方案技术章。

### 用户体验（10分）— 官方考察点：界面友好、操作便捷、交互流畅

**本作品回答**：四端统一涟漪品牌（医生指挥大屏/患者门户/家属圈/管理端）；患者端适老化模式（大字号+真高对比+焦点可视+aria-live 读屏）；健康气象把风险翻译成天气语言；DuMate 端结构化卡片输出（科室/置信度/证据链/哈希一眼可读）；大屏 LIVE/SNAPSHOT 徽章如实标注数据来源——不欺骗用户也是 UX。

**现场证据**：localhost:5173/5176 现场演示；7 张界面截图；自动演示模式 `?demo=1`。

**⚠️ 评委可能抨击 × 防御**：
- "界面是给评委看的还是给老人用的" → 防御：适老化不是加大字号（真高对比度+焦点管理+读屏支持，可现场切开发者工具验证）。

### 展示效果（10分）— 官方考察点：文档说明清晰，突出核心优势亮点

**本作品回答**：12 页应用方案（≤20 页达标）；系统卡 7 条诚实披露（Model Cards 规范）；8-10 分钟三幕录屏剧本（每条指令打一个行业痛点）；评委 5 分钟亲手体验路径；本对照表保证"每个问题都有实证兜底"。

## 三、DuMate 平台演示专项（本届评委重点关注）

1. **调用方式**：技能支持自动触发与 `/技能名` 手动调用两种方式；现场演示以手动调用为主——口播："我们显式调用技能，让每一次工具调用可观察、可审计"，与作品"可审计"主线一致。
2. **真连演示**：技能通过网关 JWT（按角色区分患者/医生令牌）真连 13 微服务后端，分诊/处方拦截/涟漪推演输出真实结构化结果+证据链；如出现 degraded 标注，如实讲解分级降级设计（本身是技术实现维度加分点）。
3. **五技能全链路叙事**：诊前分诊（含急诊主动判定）→ 涟漪推演（含处方拦截）→ 病历草稿 → 随访计划（含异常主动回传）——每条指令打一个行业痛点，收尾一句话："这不是五个孤立工具，是一条诊前-诊中-诊后的守护闭环。"

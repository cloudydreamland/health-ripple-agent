# Smart Cloud Brain Health Ripple Agent — System Card（系统卡 v1.0）

> 本文档按 Model Cards（Mitchell et al., 2019）与 System Cards 实践编写，披露本智能体的预期用途、组成、评测结果与**已知局限**。
> 与宣传性文档不同：本卡片的目的是让使用者和评审在 10 分钟内建立对本系统边界的准确预期。
> 最后更新：2026-09-18 ｜ 对应代码：main 分支

## 1. 系统是什么

**健康事件涟漪守护智能体**：当患者发生新诊断、新处方、异常指标时，系统主动推演该事件在患者生活中的多维度连锁影响（药物-生活冲突、复查窗口、并发症早期信号、家属注意事项、医疗时间学触达），量化为涟漪强度指数（RII），按时间学时机主动触达患者，并以反事实决策树 + 哈希链存证保留每一步决策证据。

**使用者**：基层全科医生（指挥大屏/队列）、患者及家属（健康涟漪页/回执）、DuMate 智能体（Skill 指令驱动）。

## 2. 预期用途（Intended Use）

- 基层医疗机构诊后场景：新诊断/新处方后的患者教育与主动随访
- 慢病长期管理：复查窗口、季节波动、节律性风险的周期触达
- 医疗质量与合规场景：AI 决策留痕、审计、责任证据导出（HL7 FHIR R4 Provenance）

**非预期用途（Out of Scope）**：急诊抢救决策、诊断、处方开具、治疗方案变更——系统输出全部为辅助建议（每次输出携带 `safetyBoundary`，终审权在医生）。

## 3. 组成与决策机制

| 层 | 组件 | 说明 |
|---|---|---|
| 推演 | 五维涟漪图谱 + RII | 确定性规则引擎：`RII=100×S×U×A×e^(−0.22(r−1))`，逐节点输出评分依据，可复算 |
| 时机 | 医疗时间学引擎 | WINDOW/RHYTHM/PERIODIC/SEASONAL 四类可计算触达，每条携带循证 Timing Card |
| 预见 | 72小时涟漪预报 | 触达 RII 强度的确定性叠加（高斯激活，无随机数），与消解闭环联动 |
| 安全 | 反事实护栏 | 双通道审计（独立关键词通道+源等级通道），FLAGGED 路径禁止下发，可覆写生成器误标 |
| 协作 | 五 Agent MDT | 分诊/处方/病历/随访/涟漪守护五视角发言，分歧显式暴露、按"患者安全优先"收敛 |
| 信任 | 印鉴链 | SHA-256 哈希链（并发安全），篡改可定位；FHIR R4 Provenance 导出（扩展承载+NIST OID） |
| 分诊 | 规则引擎 + 安全网 | 否定感知症状匹配；TriageSafetyNet 对所有 Provider（含 LLM）强制红色指征覆写 |

## 4. 评测结果（RippleBench v3，2026-09-18）

| 子集 | 结果 | 说明 |
|---|---|---|
| 分诊路由（开发集 20 例） | 20/20 | 科室+紧急度+降级三元组全对 |
| 涟漪推演（开发集 20 例） | 20/20 | 五维命中+RII 有效性+时间学覆盖 |
| 护栏（20 例） | 灵敏度 100% / 特异度 100% | 真特异度（知识库命中 MEDIUM 阴性）与防幻觉分口径均 100% |
| **盲测集（10 例 held-out）** | **10/10** | 开发期未参与调参；知识库外病例诚实空态/降级；金标准依据外部指南 |
| 消解闭环（10 场景） | 10/10 | 回执计数/消解率数学精确 |
| 端到端测试 | 27/27 | 含越权访问（403）/未鉴权（401）/患者越权审定（403）负例 + 家属圈PHI泄漏与篡改令牌断言 |
| 后端单元测试 | 63 项 0 失败 | 含哈希链 4 线程并发回归 |

评测的可信度边界：开发集金标准部分源自内置知识库，**证明的是工程链路正确性，不构成临床正确性主张**；盲测集金标准依据外部指南独立制定，检验泛化与安全底线。

## 5. 已知局限（诚实披露）

1. **知识库覆盖有限**：内置 13 条药物-生活冲突/12 条并发症信号/9 条复查窗/11 条时间学规则，覆盖糖尿病、高血压、冠心病、哮喘、慢性肾病及 9 种药物。知识库外疾病系统输出**诚实空态**（RII=0、不臆造建议），而非正确建议——覆盖面扩展是第一优先级路线图。
2. **无临床盲标**：评测金标准未经过独立医生盲标，无评分者间一致性数据；未在真实患者数据上验证。
3. **LLM 默认未接入**：默认部署 `AI_PROVIDER=mock`（结构化规则引擎）。系统按"规则为安全底线、LLM 为增强"设计（安全网红线对所有 Provider 生效），但 LLM 增强模式的端到端效果未在默认部署中体现。
4. **哈希链信任边界**：防"静默篡改"，不防御持有数据库写权限者的整链重算；生产需周期性外部锚定。
5. **预报是确定性外推**：72 小时预报基于触达计划与 RII 的确定性叠加，不包含个体生理差异与依从性建模。
6. **守护价值账本为计数型**：只统计真实发生的守护动作，不虚构"避免了 X 次死亡"的概率换算（需真实世界对照数据）。
7. **单机构演示规模**：验证环境为演示种子数据与自动化测试流量，未承受真实并发医疗负载。

## 6. 伦理与合规考量

- PHI 防护：Skill 层手机号/身份证脱敏落盘；服务层患者数据归属校验（越权 403 有回归测试）；网关 JWT 鉴权（已移除 token-in-URL 通道）
- AI 责任：每次决策证据入链可审计、可申诉、可追问（反事实树"如果选了别的会怎样"）
- 公平性：规则引擎覆盖成人/儿科/产科不同年龄层路由；知识库的语言为中文，英文症状仅部分支持
- 适老化：大字号/真高对比/焦点可视/aria-live；回执"已就医"设二次确认防误触

## 7. 路线图（按优先级）

1. 医生盲标评测集（≥50 例，双评分者）与真实世界回溯验证
2. 知识库扩展至基层 Top30 慢病/常用药，接入国家药品目录
3. LLM 增强模式（真实 key）端到端评测 + 与规则底线对比报告
4. 哈希链尾哈希外部锚定（公证服务/多方可信存证）
5. 预报引入依从性个体化建模（需真实回执数据积累）
